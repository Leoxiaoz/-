# Testing / QA（测试与质量保障规约 · 项目专属）

> 版本 v1.0（项目定制） · 依据：ROADMAP.md / SIMULATION_SPEC.md / SAVE_SPEC.md / DATABASE_SPEC.md
> 本 Skill 是本项目的**质量红线与验证流程**，不是通用教程。

## 0. 项目事实（前提，不得违背）

- 每阶段必须**可测试**，不以"UI 里能跑一次"为完成标准。
- **必测清单**（ROADMAP §6）：数据库加载与校验 / 球员·球队创建 / 转会 / 合同 / 比赛模拟（含确定性复现）/ 联赛排程·积分·升降级 / 球员成长 / 存档·读档（含迁移与损坏）/ 多赛季 1·5·10·20+。
- **确定性**：同一（数据库 + 存档 + 比赛条件 + 种子）必须可复现。
- **长期稳定性检查项**（SIMULATION §15）：财政崩坏、不可能年龄、重复/缺失球员、不可能转会、空阵容、联赛规模错误、赛程错误、指数/属性通胀、损坏合同、数据腐坏。

## 1. 何时使用

- 完成任一系统实现后。
- 提交 / 阶段验收前。
- 制定测试方案与用例清单。
- 排查质量问题（数值自洽、存档兼容、边界场景、长期稳定）。
- 多赛季回归验证。

## 2. 核心原则（项目专属）

1. **每系统必须有测试**，不以界面跑通为准。
2. **确定性优先**：关键模拟可复现（可控种子）。
3. **长期性为核心验收**：多赛季稳定性是硬指标。
4. **数据完整性优先于界面表现**。
5. **边界与异常必须覆盖**：空、零、满上限、重复操作、快速连点。
6. **可复查**：用例可追踪、结果可复现、结论可交接。

## 3. 必须检查什么（测试清单）

- [ ] 数据库：加载、完整性校验（悬空/重复 ID、缺失字段）、错误是否可定位
- [ ] 球员 / 球队创建
- [ ] 转会：是否走"谈判"闭环（非直接加入）
- [ ] 合同：到期 / 续约 / 条款
- [ ] 比赛模拟：**同输入同种子同结果**；各阶段可独立替换
- [ ] 联赛：排程 / 积分 / 升降级
- [ ] 球员成长：成长的合理性与可解释性
- [ ] 存档 / 读档：状态一致、迁移、损坏档回退
- [ ] 多赛季 1 / 5 / 10 / 20+：无崩坏 / 通胀 / 断代 / 重复 / 空阵容 / 年龄越界
- [ ] 边界：空档、满上限、重复操作、快速连点
- [ ] 数值自洽：无负数 / NaN / undefined / 越上限
- [ ] 换库场景：加载不同数据库、换库不破坏存档

## 4. 禁止做什么

- 禁止以"UI 能跑一次"视为功能完成。
- 禁止跳过确定性复现测试。
- 禁止只测单赛季就宣称"世界稳定"。
- 禁止忽略存档兼容 / 迁移 / 损坏档测试。
- 禁止静默放过失败用例或"忽略警告"。
- 禁止自行决定仍标 TBD 的验收口径（如长期稳定时长 S14/T14、目标机型性能基线 R6）。

| `documentation` | 测试结论成文、变更后同步 |
