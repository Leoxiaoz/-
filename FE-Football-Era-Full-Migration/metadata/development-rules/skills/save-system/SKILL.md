# Save System（存档系统）

> 占位框架文档。正式内容将在提供完整「游戏制作规划」（含存储方案取向）后，由制定者据此定制。

## 定位

本 Skill 聚焦游戏**存档系统**规约：存档内容与组织方式、何时读写与落盘、如何保证旧档兼容、如何容错损坏档。当前为通用框架占位，**不自行决定具体存储方案、目录结构与模块划分。**

## 适用范围

- 单机、手机端、文字/模拟经营类游戏的存档设计与维护
- 尚未最终确定存储方案（本地 / 在线、结构化 / 半结构化）的早期阶段

## 待定项（占位，不预先决定）

以下内容**保持空白**，等待「游戏制作规划」提供后再填充：

- [ ] 存储载体与读写方式（本地文件 / 平台存储 / 云同步）
- [ ] 存档内容结构与字段契约、版本号机制
- [ ] 读写时机（即时 / 关键节点 / 周期）与失败处理
- [ ] 多存档槽 / 校验与损坏容错策略
- [ ] 迁移函数清单与兼容用例

## 通用规约框架（与具体项目无关的原则占位）

1. **可读可写闭环**：存进去能完整读回，字段在创建、读取、跨周期推进后一致；缺省字段有兜底。
2. **版本与迁移**：每次数据结构调整带版本号与迁移策略，旧档可正常读写、不崩溃。
3. **写入时机明确**：明确数据何时落盘，避免在关键节点丢失进度。
4. **损坏容错**：读完需校验，损坏/不完整存档能兜底恢复（如回退/重建默认档），不卡死、不崩溃。
5. **边界安全**：为空档、满上限、重复读写、快速连点等场景不报错、不覆盖丢失、不重复发放。

## 使用方式

- 收到「游戏制作规划」后，由制定者审阅并填充「待定项」，正式定制本 Skill。
- 本文件为占位说明，暂不包含任何具体存档实现。
