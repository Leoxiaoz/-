# Game Systems / Game Logic（游戏系统 / 玩法逻辑）

> 占位框架文档。正式内容将在提供完整「游戏制作规划」后，由制定者据此定制。

## 定位

本 Skill 聚焦游戏**核心系统与玩法逻辑**的规约：系统如何划分、系统之间如何交互、数据如何在系统间流动、规则如何被校验。当前为通用框架占位，**不自行决定任何项目的技术栈、目录结构与模块划分**，也不代替制定者提前确定具体玩法细节。

## 适用范围

- 单机、手机端、文字/模拟经营类游戏的系统设计与玩法逻辑约定
- 尚未最终确定系统清单与其具体规则表现的早期阶段

## 待定项（占位，不预先决定）

以下内容**保持空白**，等待「游戏制作规划」提供后再填充：

- [ ] 核心玩法系统清单（如经营/模拟相关系统及其职责边界）
- [ ] 各系统的输入 / 处理 / 输出与相互依赖关系
- [ ] 系统间数据接口与调用约定
- [ ] 规则与数值的存放位置（集中常量表 vs 分散）
- [ ] 事件 / 状态 / 周期的推进与触发机制

## 通用规约框架（与具体项目无关的原则占位）

1. **系统单一职责**：一个系统只负责一类玩法；系统间通过明确的数据接口交互，避免互相直接改内部状态。
2. **数据流清晰**：输入来源、处理逻辑、输出结果是触发式还是轮询式，需在实现前明确。
3. **可校验规则**：每次新增/修改规则，走统一的平衡校验（见 game-architecture 中「数值循环校验」）。
4. **隔离与复用**：通用能力（如数值、时间推进、格式化）抽离复用，避免在多个系统里重复实现。
5. **不写死、可维护**：常变动的规则/数值集中管理，改一动一处。
