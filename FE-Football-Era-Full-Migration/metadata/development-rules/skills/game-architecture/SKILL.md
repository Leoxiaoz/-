# Game Architecture（游戏架构规约）

> 占位框架文档。正式内容将在提供完整「游戏制作规划」（题材、玩法、技术栈、运行平台、目标体验）后，由制定者据此定制。

## 定位

本 Skill 目标是在游戏开发的全过程提供一套稳定、可校验的工程规约，让项目在扩容时结构一致、数值循环健康、旧档可迁移。当前仅建立通用框架与流程占位，**不擅自决定任何项目的技术栈、目录结构与模块划分**。

## 适用范围

- 单机游戏（含手机端、文字/模拟经营类）项目的架构咨询、评审与维护
- 尚未最终确定技术栈、目录与模块划分的早期阶段

## 待定项（占位，不预先决定）

以下内容**保持空白**，等待「游戏制作规划」提供后再逐一填充：

- [ ] 技术栈与周边工具链（语言 / 框架 / 构建 / 其它）
- [ ] 目录结构与模块划分（源码分层、各自职责边界）
- [ ] 状态/数据管理方案（中央数据、存档格式、刷新机制）
- [ ] 数值与经济系统清单（资源、产出、消耗、上限）
- [ ] 平台与运行环境约束（单机、手机端适配、文字类 UI 风格）

## 通用规约框架（与具体项目无关的原则占位）

以下条目为通用骨架，具体细则待定制后展开：

1. **分层与职责**：视图 / 核心逻辑 / 弹窗 / 样式 / 数据的职责划分需清晰，新代码沿用既有模块划分，不另起炉灶。
2. **状态一致性**：涉及玩家/势力等核心状态的字段，在创建、存档、读取、跨周期推进后应保持一致，缺省字段提供兜底。
3. **数值循环校验**：对每一处新增/修改的资源与产出，核对「来源可得 → 消耗有处去 → 循环闭合 → 回收有出口 → 防刷防爆」。
4. **存档兼容**：数据结构变更需带版本号与迁移策略，旧档可正常读写、不崩溃。
5. **不写死、可维护**：可复用数值/规则集中管理，避免散布魔法数字。

## 使用方式

- 收到「游戏制作规划」后，由制定者审阅并据此填充「待定项」，正式定制本 Skill。
- 本文件为占位说明，暂不包含任何具体项目实现。
