# Mobile UI / UX（移动端界面与交互规约 · 项目专属）

> 版本 v1.0（项目定制） · 依据：GAME_DESIGN.md / SAVE_SPEC.md / DATABASE_SPEC.md / ROADMAP.md
> 本 Skill 是本项目的**界面与交互红线**，不是通用教程。

## 0. 项目事实（前提，不得违背）

- **移动端优先**，终态 Android App。
- 游戏是**文字 / 数据驱动**；UI 服务于信息，**不是视觉表现**。
- **UI 与核心逻辑分离**：UI 不直接改写模拟状态。
- 要求：信息驱动、快速导航、清晰层级、触摸友好、避免不必要动画与后台处理。
- **可解释性**：重要模拟结果应能向玩家展示"为什么"。

## 1. 何时使用

- 设计界面、布局、导航结构。
- 定义触摸交互与手势。
- 评审视觉一致性与信息层级。
- 处理空态 / 加载 / 错误等边界界面。
- 呈现模拟结果与其解释。

## 2. 核心原则（项目专属）

1. **一目了然**：核心信息优先可见，层级清晰，关键操作入口可达。
2. **触摸友好**：目标尺寸与间距适配手指，减少误触。
3. **即时反馈**：每次操作有明确反馈，可退出回上一级。
4. **一致性强**：复用统一组件与样式变量，避免散落魔法数值。
5. **边界界面完整**：空态、加载、错误、满限、重复点击都有合理表现，不卡死、不白屏。
6. **可适配**：适配不同屏幕并保持核心交互可用。
7. **可解释**：能显示结果成因（如状态下降、士气变化、AI 决策理由）。
8. **不造假功能**：不做无实现的控件或设置。

## 3. 必须检查什么（检查清单）

- [ ] UI 是否与 Core 分离（不直接改模拟状态）？
- [ ] 信息层级是否清晰？关键入口是否可达？
- [ ] 触摸目标尺寸 / 间距是否合适？
- [ ] 每次操作是否有反馈？是否可退出？
- [ ] 空 / 加载 / 错误 / 满限 / 重复点击是否有表现？
- [ ] 是否避免不必要动画与后台处理？
- [ ] 重要结果是否可解释？
- [ ] 是否存在"看起来能点但无作用"的假控件？
- [ ] 多屏幕适配下核心交互是否仍可用？

## 4. 禁止做什么

- 禁止在 UI 层编写业务 / 模拟逻辑。
- 禁止过度装饰、不提升理解的复杂 UI。
- 禁止假功能控件 / 未实现的设置项。
- 禁止不必要的动画与常驻后台处理。
- 禁止把桌面端的复杂交互直接堆到移动端。
- 禁止自行决定仍标 TBD 的界面相关设计（时间推进的 UI 表达 T1、存档槽 UI V3 等）。

## 5. 与其他 Skill 协作

| Skill | 协作方式 |

| `documentation` | 交互规范与已知限制同步 |
