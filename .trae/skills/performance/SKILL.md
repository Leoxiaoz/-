# Performance（性能规约 · 项目专属）

> 版本 v1.0（项目定制） · 依据：GAME_DESIGN.md / ROADMAP.md / SIMULATION_SPEC.md / SAVE_SPEC.md
> 本 Skill 是本项目的**性能红线与评审流程**，不是通用教程。
> 说明：本 Skill 由制定者明确要求在新清单外**保留并定制**（原为占位骨架）。

## 0. 项目事实（前提，不得违背）

- **移动端优先**；要求快加载、低内存、响应式。
- 避免不必要的动画与后台处理。
- 长期模拟（多赛季、AI 决策、大量比赛）必须控制在**性能预算**内（SIMULATION S13/T12）。
- 性能优先**不得**牺牲数据完整性与存档兼容。

## 1. 何时使用

- 排查性能瓶颈（加载慢 / 卡顿 / 内存高）。
- 做性能评审。
- 规划性能优化。
- 制定性能指标 / 基线。
- 涉及大规模模拟、AI 决策、数据加载、存档读写时。

## 2. 核心原则（项目专属）

1. **性能意识前置**：设计期即考虑数据规模与读写频率，避免后期大改。
2. **避免重复计算**：可缓存的中间结果、可复用的数据不重复生成。
3. **按需加载与释放**：资源与数据按需加载、不用即释放，避免随赛季推进无限累积。
4. **写入有节制**：存档 / 状态写入时机合理，避免高频落盘。
5. **量化可测**：优化前后有可对比指标，避免"凭感觉优化"，改动后可回归验证。
6. **不牺牲可维护**：优化不得破坏架构、数值循环与存档兼容。
7. **技术服务于设计**：不得以"降级核心玩法"换取性能；若必须权衡，**先提简化方案**给制定者。

## 3. 必须检查什么（检查清单）

- [ ] 是否引入 O(n²) 或每帧/每节拍的重复计算？
- [ ] 是否随赛季推进无限累积对象 / 历史 / 缓存？
- [ ] 存档写入是否过于频繁或体积过大？
- [ ] 数据加载是否全量抢占内存？能否按需 / 流式？
- [ ] AI 与批量比赛模拟（长期跑赛季）是否在预算内？
- [ ] 是否有可对比的性能指标？
- [ ] 优化是否破坏了架构 / 数值循环 / 存档兼容？
- [ ] 是否引入了不必要的动画或常驻后台处理？

## 4. 禁止做什么

- 禁止凭感觉优化而无指标。
- 禁止为性能牺牲数据完整性 / 存档兼容。
- 禁止引入不必要动画或常驻后台处理。
- 禁止用"删除 / 弱化核心玩法"换取性能（须先提方案）。
- 禁止在未测出瓶颈时进行投机性优化。
- 禁止自行决定仍标 TBD 的性能预算 / 基线（R6 目标机型与基线、S13/T12 AI 计算预算）。
