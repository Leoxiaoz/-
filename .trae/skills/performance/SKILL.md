# Performance（性能优化）

> 占位框架文档。正式内容将在提供完整「游戏制作规划」（含技术栈与平台约束）后，由制定者据此定制。

## 定位

本 Skill 聚焦游戏**性能规约**：加载、渲染、内存、读写与资源管理的优化约定，以及性能评审与指标流程。当前为通用框架占位，**不自行决定具体技术栈、目录结构与模块划分。**

## 适用范围

- 单机、手机端、文字/模拟经营类游戏的性能优化与评审
- 尚未最终确定技术栈与性能指标口径的早期阶段

- [ ] 主要性能瓶颈关注面（渲染 / 逻辑 / 读写 / 内存 / 资源）
- [ ] 数据分析方式与评估口径/工具
- [ ] 资源与数据加载/缓存/释放策略
- [ ] 优化优先级与发布准入门槛

## 通用规约框架（与具体项目无关的原则占位）

1. **性能意识前置**：结构设计时即考虑规模与读写频率，避免后期大改。
2. **避免重复计算**：可缓存的中间结果、可复用的资源与数据不重复生成。
3. **按需加载与释放**：资源与数据按需加载、不用即释放，避免随玩法推进无限累积。
4. **写入有节制**：存档/状态写入时机合理，避免高频落盘拖慢性能。
5. **量化与可测**：优化前后有可对比的指标，避免"凭感觉优化"，改动后可回归验证。
6. **不牺牲可维护**：优化不得破坏既有架构、数值循环与存档兼容。
