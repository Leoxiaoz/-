# Database / Data Modeling（数据库 / 数据建模）

> 占位框架文档。正式内容将在提供完整「游戏制作规划」（含存储方案取向）后，由制定者据此定制。

## 定位

本 Skill 聚焦游戏**数据建模与存储**规约：配置数据与动态数据如何区分和建模、存档如何组织、变化的数据结构如何兼容与迁移。当前为通用框架占位，**不自行决定具体存储方案、目录与模块划分。**

## 适用范围

- 单机、手机端、文字/模拟经营类游戏的数据结构与存档设计
- 尚未最终确定存储方案（本地文件 / 结构化存储 / 云同步等）的早期阶段

## 待定项（占位，不预先决定）

以下内容**保持空白**，等待「游戏制作规划」提供后再填充：

- [ ] 存储方案取向（本地 / 在线、结构化 / 半结构化、可配置与否）
- [ ] 数据实体清单（配置表、动态状态、排行榜、成长/经济数值等）
- [ ] 字段与契约定义、类型约束、默认值兜底规则
- [ ] 存储读写时机（即时写 / 周期存 / 关键节点存）
- [ ] 版本号机制与迁移函数清单

## 通用规约框架（与具体项目无关的原则占位）

1. **配置与动态分离**：可配置内容与玩家动态状态分开建模，便于平衡调整与重置。
2. **契约明确**：字段命名、类型、取值范围与默认值需有明确约定；读取端对缺失字段提供兜底。
3. **版本与迁移**：数据结构变更需带版本号与迁移策略，旧档可正常读写、不崩溃。
4. **读写策略清晰**：明确各数据在何时写入、何时读取、何时落盘，避免数据不一致。
5. **边界兜底**：为空、为零、达上限、重复操作等边界场景不报错、不重复发放、不越界。

## 使用方式

- 收到「游戏制作规划」后，由制定者审阅并填充「待定项」，正式定制本 Skill。
- 本文件为占位说明，暂不包含任何具体数据结构或存储实现。
